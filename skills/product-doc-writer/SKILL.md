# 产品说明文档 Skill

## 概述

给指定的产品 / 语言 / 应用写说明文档。文档一律拆成多个独立文件，禁止合并成单个 README。默认中文，命令只保证 Linux Mint 可用。

## 工作流程

### 1. 确定对象与信息来源

- 确认文档对象：具体产品名 + 版本（用户没给版本就问，或按本机已安装版本为准）。
- 信息来源优先级：本机实测 > 官方文档 > 通用知识。涉及安装命令时，优先在本机验证（`apt list --installed`、`which`、`--version`）。
- 信息不足时先问用户，不要编造版本号和命令。

### 2. 确定文档目录

按以下顺序判断（这样做是为了避免把文档和配置文件混在一起）：

1. 列出当前目录内容（用 read 目录，不要用 bash ls）。
2. 如果当前目录含有配置文件，即判定为配置目录。配置文件指：`*.json`、`*.yaml`/`*.yml`、`*.toml`、`*.ini`、`*.conf`、`*.config.js`，或 `.config/`、`.opencode/`、`config/` 子目录，或 `opencode.json` 这类工具配置。
3. 是配置目录 → 新建 `doc/` 子目录，文档写在 `doc/` 下。
4. 不是配置目录 → 直接用当前目录作为文档目录。
5. 拿不准（例如空目录、既有配置又有项目文件）→ 直接问用户用哪种，不要猜。

### 3. 写多文件文档

禁止把安装、配置、使用写进同一个文件。最小拆分如下：

- `install.md` — 安装（系统要求、本机安装命令、验证安装成功的方法）
- `config.md` — 配置（配置文件位置、关键配置项、最小可用配置示例）
- `usage.md` — 使用（最常用 3-5 个命令/操作、每个一句话说明 + 一个可运行示例）

内容量大时进一步拆目录：

- 任一主题预计超过约 100 行，或配置项 / 使用场景明显分属不同方面时，改为目录：`install/`、`config/`、`usage/`，每个目录下按子主题拆文件（如 `usage/basic.md`、`usage/advanced.md`）。
- 每个目录下放一个 `README.md` 只写索引（列出该目录下各文件一句话简介），不放实质内容。

每个文件结构固定：

```markdown
# <主题>
## 前提
## 步骤 / 内容
## 验证
```

### 4. 风格要求

- 简洁：只写本机（Linux Mint）验证过的路径和命令，不写 Windows / macOS / 其他发行版分支。不确定的写法宁可不写。
- 每个命令都应可直接复制运行；需要占位符时用 `<...>` 标明。
- 不写面面俱到的参考手册，只覆盖最常用的安装、配置、使用路径。
- 写完后用 read 检查实际 diff，确认没有污染配置目录。
