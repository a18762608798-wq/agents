# 人机认知协作：结果可信度、选择性理解与认知正反馈循环

> 与 [README.md](./README.md) 的互补关系：COC（面向变更的计算）解决的是**外部产出的演化与验证闭环**——`State -> Change -> Artifact Graph -> Approval -> Actions -> Evidence -> State'`，让变更成为一等对象、让证据自动验证状态跃迁。本文解决的是**内部认知闭环**：当 AI 承担大量推导与实现时，人类如何通过**选择性理解关键思想**，让 AI 的能力扩展与自身认知成长形成**正反馈循环**。前者管「产出可信」，后者管「人也在长进」，两者合起来才是完整的人机协作。

## 一、区分两个维度：结果可信度与个人理解深度

### 维度 A：我凭什么相信 AI？

两个独立的支点：

1. **形式正确性**：推导、代码、证明在形式上是否站得住——类型检查通过、测试全绿、证明可被机器检验、逻辑链条无缺口。这是可以**外包给工具**的部分。
2. **语义与目标一致性**：AI 做的是不是我想要的——问题定义对不对、假设是否符合现实、结论是否回答了真正的问题、有没有在错误的目标上漂亮地完成工作。这是**无法外包**的部分，只能由人判断。

形式正确不等于方向正确。一份形式完美、目标跑偏的产出，可信度是零。

### 维度 B：我自己究竟理解到了什么程度？

理解不是一个开关，而是一个分层的谱系：

- **L1 结构理解**：知道整体在做什么——模块如何划分、证明分几个阶段、数据从哪来到哪去、每一步在整个论证中的位置。不要求能独立复现细节。
- **L2 机制与核心思想的理解**：知道**为什么**这样做——关键引理为什么成立、瓶颈在哪里、突破点靠什么想法撬动、哪一步是整个论证的承重墙。能向别人解释，能回答「如果不这样会怎样」。
- **L3 生成性理解**：能**独立重建**——不看答案从头做出同等或更好的结果，能把这套思想迁移到新问题上，能发现原方案的缺陷并改进。这是理解的最高形态：知识已经变成自己的生成能力。

### 为什么要把它们分开？

以 Lean 证明助手为例：机器检查通过的证明，**结果可信度是满分**——不存在「大概对」，要么通过要么不通过。但这与我是否理解这个证明**毫无关系**：我可以完全看不懂某个 tactic 块在做什么，同时百分之百信任它的结论。

把两个维度混为一谈，会导致两种典型错误：

- 因为结果可信，就以为自己理解了——认知幻觉；
- 因为自己不理解，就以为结果不可信——无谓的重复劳动。

**核心结论**：要同时维护两张清单——**结果可信度**（哪些产出经过了形式与语义的双重把关）与**自身真正掌握的知识范围**（哪些东西我真的达到了 L2/L3）。两张清单各自诚实，互不冒充。

## 二、不必亲自完成所有推导，但必须明确哪些部分被跳过了

在 AI 深度参与的工作流里，同一份产出的不同部分可以合理地处于四种状态之一：

| 状态 | 含义 | 典型场景 |
| --- | --- | --- |
| **已验证** | 形式上确认正确，但我未必理解其内部机制 | 机器检查通过的证明、全绿的测试、通过 lint 与类型检查的代码 |
| **已理解** | 达到 L2：知道它为什么成立、在整体中起什么作用 | 精读过的关键引理、亲手推导过的核心步骤 |
| **已掌握** | 达到 L3：能独立重建并迁移 | 自己重写过的模块、复现过的推导 |
| **尚未理解或验证** | 既没检查过也没弄懂，只是「AI 说做完了」 | 长推导的中间细节、自动生成的辅助脚本 |

这四种状态**并存是合理的**。要求所有部分都达到「已掌握」不现实，也会把人的注意力消耗在低价值细节上；中间状态本身没有问题——**问题在于标记错位**。

必须避免的误区：**把「AI 已经完成」误认为「自己已经理解」**。AI 完成的是产出，不是你的认知。诚实的做法是给每个部分贴上它真实的状态标签，让「尚未理解或验证」的区域可见、可枚举、可后续处理，而不是让它们藏在「做完了」的表象之下。

## 三、深入研究的关键，是选择性理解，而不是平均分配注意力

复杂理论证明中，各个部分的价值极不均匀。典型的三类处理：

1. **基础引理**：技术性铺垫，标准套路，出错概率低。通常**已验证**即可，不必逐条精读。
2. **连接模块的关键引理**：把各个部分粘成整体的枢纽，一旦理解，全局结构豁然开朗。值得投入时间达到 **L2**。
3. **决定突破的核心思想**：整个论证真正的杠杆点——那个「原来可以这样想」的瞬间。值得反复咀嚼，力求 **L3**，因为它是可以带走、迁移到下一个问题的东西。

选择深入对象的三个维度：

1. **重要性**：它在整体论证中承担多少重量？删掉它整个结构会塌吗？
2. **脆弱性**：它有多容易错？假设是否微妙、结论是否反直觉、边界条件是否密集？脆弱的地方最需要人眼复核。
3. **延展性**：理解它能带来多少额外收益？它是否是通用方法、能否迁移到其他问题、是否揭示了一类现象的共性？

三个维度的交集，就是注意力应该汇聚的地方。**平均分配注意力是对认知资源的浪费**：把 L3 级别的精力花在基础引理上，和只用「已验证」打发核心思想，是同一类错误的两个方向。

## 四、最终形成的应该是一个认知上的正反馈循环

```text
① AI 扩展探索范围
      │  产出大量推导、证明、实现，把可能性边界推远
      ▼
② 人类理解整体结构
      │  建立 L1：知道每块东西在做什么、为什么在这里
      ▼
③ 选择性深入重建
      │  对关键引理与核心思想追求 L2 / L3，亲手复现
      ▼
④ 提升自己的认知能力
      │  眼界、品味、直觉随理解而增长
      ▼
提出更好的问题 ──► 进入下一轮探索（回到 ①）
```

关键在于闭环的方向：**AI 扩展的是探索范围，人扩展的是理解能力**。如果只有 ① 没有 ②③④，人会被产出淹没，长期停留在「验证者」角色；如果有 ②③④ 而没有 ①，人只能在自己的既有视野里打转。两环相扣，人的提问质量提高，AI 的探索才越来越有方向；AI 的探索越远，人能理解与重建的素材就越高级——这才是**认知上的正反馈循环**。

## 五、落地映射：在 `knowledge/`（`CON-/PRF-/RES-`）体系中的实操

上述框架在 `knowledge/` 知识库（`CON-*` 概念、`PRF-*` 证明、`RES-*` 结果综合）中的落地方式如下；推导书写的关键词块规范见 `skills/structured-proof`。

三层文件的边界：`CON-*` 是不绑定具体协议参数（如 $M, K$、噪声模型）的原子定义/公理/经典引理，作为最底层基石；`PRF-*` 是针对单一命题的完整算式推导链（`GIVEN -> HAVE -> SUFFICES -> BY -> THEREFORE -> QED`），引用 `CON-*` 或底层 `PRF-*`；`RES-*` 是完整研究产出或协议方案（理想无噪或含噪鲁棒均可），含协议设定（`ASSUME`/`REQUIRE`）、核心构造、`PROPERTY` 结论、`CHECK` 自检与按需可选的数值验证（以 `RES-*` 文件末尾的 `## VERIFY` 章节呈现，脚本与数据存于 `note/VER-*/` 目录），并用 `BY: [PRF-*]` 链接下层证明。判据：绑定具体协议/实验参数即 `RES-*`，纯推导链即 `PRF-*`，无协议参数的原子陈述即 `CON-*`。

### 维度 A：结果可信度的物理/科研落地

物理与量子计算的推导往往不是纯数学形式问题（Lean 之类的证明助手或纯符号计算未必适用），两个支点的实现方式相应调整为：

1. **形式/结果正确性**主要依靠在 `RES-*` 层设计**小规模数值验证方案**（**按需可选，非必选**：许多 `RES-*` 的结论是已知明确结果，无需每次都跑数值验证；证明完成后由 AI 简短提醒用户，由用户按需选用，确认后再执行）：在 `RES-*` 文件末尾以**二级标题 `## VERIFY` 章节**（而非 `**VERIFY:**` 关键词块）记录验证状态（含状态、目录与按验证项分点的内容），脚本与数据放在同级 `note/VER-<名称>/` 目录（已在 git 中忽略）。数值验证不必覆盖一般定理，但要覆盖到足以暴露公式错误、符号约定错误与量级错误的规模。
2. **语义与目标一致性**主要依靠 `INTERPRET`（物理含义）、`CAVEAT`（前提限制）与 `CHECK`（解析极限/特例检验）在文中显式陈述。其中特例与反例的审视必须由**人类主导判断**：AI 顺着自身的证明过程容易陷入同一盲区，只有人从外部选取反例与极限情形，才能有效检验「结论是否回答了真正的问题」。

### 维度 B：个人理解深度（L1–L3）的去教条化落地

- **L1（结构理解）**：在 `knowledge/` 体系中天然体现为 `TOP-* -> RES-* -> PRF-* / CON-*` 的网状依赖结构。尺度是相对的：在课题层看一个 `RES-*` 依赖哪些 `PRF-*` / `CON-*`；在单篇证明内部看 Phase 划分与 `SUFFICES` 归约。持有这张依赖地图即为 L1，不要求复现全部细节。
- **L2（关键机制理解）**：「关键引理/关键步」因人而异，没有客观统一标准——AI 可以辅助指出哪些步骤动用了特殊物理假设或非平凡归约，但**由人自主选择要亲自手推的关键域**。日常标记无需复杂的四态标签：仅以章节标题为单位，对主要由 AI 生成、自己尚未亲自推导消化的部分打上 `[AI]` 尾标，推通消化后移除即可。
- **L3（生成性理解）**：不需要任何标记或硬性标准。把维度 A 的验证与 L1/L2 的选择性重建做好后，迁移能力与提出新方法是水到渠成的自然结果，不应人为设卡。

## 六、核心凝练与边界限定

> **AI 负责把边界推远，人负责在边界上建立理解。结果可信度靠验证与目标对齐，个人成长靠选择性地深入重建。两者分开维护、同步推进，人机协作才会形成正反馈，而不是人被产出淹没、或人被锁死在重复劳动里。**

**结构理解与独立重建之间的桥梁**：L1（结构理解）是通往 L3（独立重建）的必经之路，但不是终点。只停留在 L1，理解是脆弱的——换个表述就认不出来；直接追求 L3 而没有 L1 铺垫，会在细节里迷路。正确的路径是：先看清整体骨架，再挑承重的部位亲手重建，让结构理解逐步「长」成生成能力。

**何时走完整个循环，何时只需结构理解与适当验证**——按价值判断分流：

- **走完整循环（L1 -> L2 -> L3）**：核心思想、决定性引理、你打算长期使用或迁移到其他问题的方法、你希望成为自己研究品味一部分的领域。
- **结构理解 + 适当验证（L1 + 已验证）**：大量技术性细节、一次性使用的辅助工具、标准套路的堆叠、其他领域只需借用的结论。

未来需要培养的三种核心能力：

1. **知道整体在做什么**——随时持有全局地图，不迷失在细节里；
2. **知道哪些关键部分值得亲自理解**——把有限的认知预算花在承重墙上；
3. **知道如何把理解转化为下一次创造**——让每一次深入都变成下一轮探索的杠杆。

这三种能力合起来，就是人机认知协作时代真正的护城河。
